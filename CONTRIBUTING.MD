# OpenCobol2 Code of Conduct

## Purpose

OpenCobol2 is an open-source technical project intended for a broad community of COBOL developers, mainframe professionals, software engineers, students, educators, and contributors from other technical backgrounds.

We want project spaces to support serious technical disagreement, careful code review, experimentation, and learning without personal hostility or harassment.

## Expected behavior

Participants are expected to:

* Treat other contributors with respect.
* Critique code, architecture, documentation, and technical claims rather than attacking people.
* Give review feedback that is specific and actionable.
* Accept reasonable technical correction without retaliating against the person providing it.
* Respect differences in experience, language, background, platform, and development environment.
* Allow contributors to ask questions without ridicule.
* Assume good faith when the available facts reasonably support it.
* Correct mistakes openly when new evidence changes the technical conclusion.
* Protect private credentials, server information, mainframe details, and other sensitive data encountered during project work.

Strong disagreement is allowed.

A contributor may say that an implementation is incorrect, unsafe, unmaintainable, poorly tested, or architecturally incompatible with the project.

Technical criticism must remain focused on the work and the evidence.

## Unacceptable behavior

The following behavior is not acceptable in OpenCobol2 project spaces:

* Harassment or sustained personal attacks.
* Discrimination or degrading comments based on personal characteristics.
* Threats of violence or encouragement of harm.
* Stalking or deliberate intimidation.
* Doxxing or publication of another person's private information.
* Sexually explicit or sexualized conduct directed at another participant without consent.
* Deliberate impersonation.
* Spam or repeated bad-faith disruption.
* Knowingly submitting malicious code while misrepresenting its purpose.
* Deliberately exposing authentication tokens, credentials, private server information, or confidential system data.
* Retaliation against a person for making a good-faith conduct report.
* Repeatedly derailing technical discussions after a maintainer has asked that the discussion return to scope.

## Technical review culture

OpenCobol2 is modernizing software with significant historical and enterprise context.

Contributors must not ridicule another participant merely for:

* Working with COBOL.
* Working on a mainframe.
* Maintaining legacy systems.
* Being unfamiliar with COBOL.
* Being unfamiliar with a modern Python or Qt practice.
* Developing on Windows, Linux, macOS, or another supported environment.
* Using a different GnuCOBOL installation or toolchain layout.

Claims about compiler behavior, APIs, operating systems, standards, and external services should be supported with reproducible evidence or authoritative documentation when the issue is disputed.

Maintainers may reject a technically weak contribution without treating the contributor disrespectfully.

Contributors may challenge a maintainer's technical decision without becoming abusive.

## Scope

This Code of Conduct applies to:

* The OpenCobol2 repository.
* Issues.
* Pull requests.
* Code review.
* Project discussions.
* Official project communication channels.
* Project-managed plugin or extension spaces.
* Public conduct by a person who is explicitly representing themselves as acting on behalf of OpenCobol2.

Independent third-party communities are not automatically governed by OpenCobol2 merely because they discuss or use the project.

## Enforcement

Project maintainers are responsible for interpreting and enforcing this Code of Conduct.

Depending on the seriousness, frequency, and context of the behavior, maintainers may:

* Ask a participant to stop.
* Edit or remove inappropriate content where the platform permits.
* Close or lock a discussion.
* Reject a contribution.
* Issue a warning.
* Temporarily restrict participation.
* Permanently restrict participation.
* Report conduct to the hosting platform when appropriate.

Enforcement decisions should be proportionate and based on the available evidence.

A good-faith technical disagreement is not a conduct violation merely because the discussion is direct or critical.

## Reporting conduct concerns

Do not place sensitive personal information in a public issue.

Where available, use GitHub's reporting or blocking tools and contact the project maintainer using the contact method published on the maintainer's GitHub profile.

If a public repository issue is the only practical way to establish contact, post only a minimal request for private maintainer contact. Do not include sensitive allegations, private identifying information, credentials, or confidential system details in that public issue.

Reports made in good faith will be considered based on the available evidence and project scope.

Knowingly fabricated reports or deliberate abuse of the reporting process may themselves be treated as a conduct violation.

## No retaliation

Retaliation against a person for raising a good-faith concern is prohibited.

This does not prevent maintainers from addressing unrelated conduct or technical issues involving a reporting person when those issues are supported by independent evidence.

## Project standard

The goal of this Code of Conduct is not to eliminate blunt technical discussion.

The standard is simple:

**Be serious about the work, direct about the evidence, and respectful toward the people doing it.**
